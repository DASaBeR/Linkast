# Phase 5 report: installer and beta

**Status:** Ready for a first draft release of **0.2.0-beta.1**. Installer, updates, pinned FFmpeg, security fix and documentation are built and validated on the development PC. Still open:
- the first real GitHub release, run through the workflow;
- code signing;
- three FFmpeg libraries whose exact source can't be identified;
- the beta-tester field tests in section F.

**Test machine:** Windows 11 build 26200, i5-12400F, RTX 3070, Iriun Webcam (phone not connected), MediaMTX test ingest.

## What was built

- **Installer and updates (Velopack 1.2.161, MIT).**
  - What gets built:
    - `LinkastApp-win-Setup.exe`, a per-user install with no admin prompt, Desktop and Start-menu shortcuts and an entry in Settings › Apps;
    - a portable zip that can also update;
    - the update feed.
  - The package id `LinkastApp` keeps the install folder apart from the data folder `%LOCALAPPDATA%\Linkast`, so uninstalling never deletes settings or the encrypted key.
- **Update policy as decided:**
  - one check at start-up, plus **Check for updates**;
  - a newer version appears only as accent-coloured text next to the button ("Version x.y.z is ready to update");
  - no dialog, no automatic install;
  - **Update now** downloads, installs and restarts. It is disabled while live.
  - A start-up check that finds nothing, or can't reach GitHub, shows nothing.
  - Releases come from `DASaBeR/Linkast`, a single build setting.
- **About window** with the GPL notices: copyright, no warranty, license, third-party notices, the FFmpeg build and source, and a link to Linkast's source.
- **App icon** (generated by `tools/make-icon.ps1`) for the executable, window, shortcuts and installer.
- **Pinned FFmpeg.**
  - It is now the 9.0.1 **essentials** build, verified by SHA-256 for both the archive and `ffmpeg.exe`.
  - It has every feature Linkast uses; the full integration suite passed on it.
  - It is less than half the size of the previous build (98 MB against 212 MB for `ffmpeg.exe`).
- **FFmpeg corresponding source.**
  - `tools/fetch-ffmpeg-sources.ps1` assembles FFmpeg's release tarball plus every statically linked library at its exact version or commit: 43 entries in `tools/ffmpeg-sources.json`. For MSYS2-provided libraries it uses the MSYS2 source packages, which include the patches that were built.
  - The result is published with each release as `ffmpeg-9.0.1-corresponding-source.zip` (562 MB).
- **Security.**
  - **The stream key is no longer on FFmpeg's command line.** It used to be readable in Task Manager. The relay now writes the real key into FFmpeg's RTMP publish commands in place of a same-length random placeholder; it handles keys split across chunks or reads and falls back safely.
  - The full review is in [security-review.md](../security-review.md).
  - AsyncIO's license was verified (MPL-2.0, GPL-compatible).
- **Release automation.** The [release workflow](../../.github/workflows/release.yml) runs on a version tag:
  - it checks the tag against the version, builds and tests;
  - it downloads the previous release for delta updates;
  - it packages and assembles the FFmpeg source, failing on any download error;
  - it creates a **draft** release, which a maintainer reviews and publishes ([releasing.md](../releasing.md)).
- **Docs:**
  - [compatibility-matrix.md](../compatibility-matrix.md);
  - [releasing.md](../releasing.md);
  - [security-review.md](../security-review.md);
  - updated [licensing.md](../licensing.md) and THIRD-PARTY-NOTICES;
  - release notes;
  - an Install section in the README;
  - field tests F1–F6.

## Open items

| Item | Why it matters | Plan |
|---|---|---|
| **First GitHub release** | The workflow, delta download and GitHub update source are only proven once a real release exists. | Push the repository to `DASaBeR/Linkast`, tag `v0.2.0-beta.1`, review the draft, then publish. |
| **x264 and x265 sources** | Their hosts (VideoLAN, Bitbucket) were unreachable from the development network. | On GitHub's runners x264 was fetched at its exact revision; x265's commit turned out not to be public (see the next row). |
| **Four FFmpeg libraries without identifiable source** | cairo "1.18.5", libgme "0.6.6" and libva "2.25.0" are unreleased git snapshots whose commits gyan.dev didn't record, and x265's commit `9ddc216` isn't in its public repository. bzip2, xz and zlib versions aren't recorded either. Distributing the binary without their exact source is a GPL compliance gap. | Listed in `SOURCES.txt` and [licensing.md](../licensing.md). Closed by building FFmpeg ourselves from pinned sources; recommended before 1.0, ideally before a wide public beta. |
| **Code signing** | SmartScreen warns, and update trust rests on the GitHub account alone. | OV certificate or Azure Trusted Signing; Velopack can sign during packaging. |
| **Hardware beyond the dev PC** | AMD and Intel encoders, other webcams, Windows 10 | [Compatibility matrix](../compatibility-matrix.md) and field tests. |
